#### 真正 Root Cause

**OpenClaw gateway 從 `gateway.systemd.env` 讀 env vars，不是從 `.env` 讀**

從 systemd service file `~/.config/systemd/user/openclaw-gateway.service`：
```ini
EnvironmentFile=-/home/clawuser/.openclaw/gateway.systemd.env
```

#### 三個 token 比對（21:54 驗證）

| Source | Length | Prefix | Status |
|--------|--------|--------|--------|
| `.env` | 186 chars | `THAAwfTxeTeEZABYmFyRUNJb1…` | 60 天 long-lived，**有效**（refresh 確認） |
| `gateway.systemd.env` | 186 chars | `THAAwfTxeTeEZABYlk2TXBKcH…` | **7/28 dump，過期 28+ 天** |
| `gateway process.env` | 186 chars | = `gateway.systemd.env` | = `gateway.systemd.env` |

#### 驗證
```bash
curl -s "https://graph.threads.net/v1.0/me?access_token=$GATEWAY_TOKEN"
# → 500 (token 過期)

curl -s "https://graph.threads.net/v1.0/me?access_token=$ENV_TOKEN"
# → 200 OK (token 有效)
```

#### cron agent 為什麼失敗

從 OpenClaw source `dist/server-cron-Cwg2hJro.js:3821`：
```js
env: markOpenClawExecEnv({ ...process.env })
```

cron agent 用 `gateway.process.env` spread，而 `process.env` 內 token 來自 `gateway.systemd.env`（過期）。

#### 為什麼「測試文能發，cron 不能」

- 我手動 publish：直接讀 `.env`（用新 token）→ 200 OK
- cron agent：讀 `gateway.process.env`（過期 token）→ 500

**差異不是 API、不是 app，是 env file 同步問題。**

#### 短期解法（Hubert 自己執行）
1. **更新 `gateway.systemd.env` 內 `THREADS_ACCESS_TOKEN`**：把 `.env` 內的新值（`mFyRUNJb1…`）複製過去
2. **Restart OpenClaw gateway**：`systemctl --user restart openclaw-gateway`
3. **驗證**：cron 12:00 / 20:00 應該自動恢復

或者**最簡單**：把 `~/.openclaw/gateway.systemd.env` 內容整個換成 `~/.openclaw/.env` 內容（覆蓋）。

#### Self 反思

Session 1 我推論「process.env 凍結」是對的方向，但**沒追到 root cause**。

我找到 cron agent 用 `{ ...process.env }`，所以判斷 gateway 啟動時 freeze 的值 — **方向對，但沒追到「process.env 從 gateway.systemd.env 讀」這層**。
