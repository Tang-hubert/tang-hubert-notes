## What I Learned
- 三層架構 sync 死角 — `sync-canonical.sh` 只同步 canonical files、`sync-mirror.sh` 只同步 dev → main mirror、`sync-producer-config.sh` 只同步 `config.yaml`，**沒人同步 `knowledge/` 內的 KB .md 檔案到 L3** → 修法新增 `scripts/sync-kb.sh`
- LLM prompt 的「轉報格式」不可外洩 — SOUL.md / main_idea.md 定義的轉報格式（🔔【客服轉報通知】）是給後台 manager 用的，LLM 看到格式就會複製到客戶回覆 → 修法在 prompt 裡明確標註「此格式只給 manager 用，客戶回覆走 config.handoff.customer_reply」
- fuzzyTriggers 範圍決定 handoff 觸發頻率 — 關鍵字「貴」「下次」「算了」太寬 → 日常對話誤觸 → 修法使用完整詞組（`爛掉了`、`算便宜一點`、`改到明天`、`算了不訂`）避免子字串匹配
- transferRules 不只 code 邏輯要修，prompt 也要同步修（同一個 bug 可能從兩邊觸發）
- 新增任何 sync 腳本前先 grep 所有 `sync_*.sh` 看誰覆蓋什麼
- 客戶轉真人回覆走 `config.handoff.customer_reply`（固定話術），**不是由 LLM 生成**

### Hubert 真實對話測試抓出 4 大問題（12.jpg + 13.jpg + 14.jpg）

#### 問題 1：開團日期沒讀 config
- 客戶問「最近有哪天開團？」→ bot 回「我沒辦法直接給您確切的日期哦😅」
- 客戶問「我要煙燻雞跟珍珠丸 各一份 這樣多少錢」→ bot 回「菜單資料讀不到，請專人確認」
- **根因**：L3 runtime 沒 `knowledge/tenants/chicken/01_product.md`（KB 整個沒同步到 L3）
- **修法**：
  - `scripts/sync-kb.sh`（Round 37.31）rsync mirror L1 → L3
  - `main_idea.md` §三 修：開團日期、地址確認、配送時段、價格都應由 AI 自行讀 config/KB，**不再列為轉真人理由**
  - `SOUL.md` §六 加強：「客服轉報通知」格式只用在後台管理員通知，**絕不出現在客戶的 LINE 訊息**

#### 問題 2：轉真人太頻繁
- 客戶問簡單問題（最近哪天開團 / 現在還能訂嗎 / 多少錢）bot 立即說「我幫您轉給真人確認」
- **根因**：`transferRules.js` semanticMatch 的 fuzzyTriggers 太寬
  - 「貴」/「太貴」→ discount_request（但「多少錢」也會誤觸）
  - 「下次」→ reschedule_request（但「下次開團」也會誤觸）
  - 「算了」→ cancel_request（但日常用語也會誤觸）
- **修法**（Round 37.32）：把 fuzzyTriggers 縮窄為完整詞組
  - complaint: `爛掉了 / 很糟糕 / 雞肉壞掉 / 投訴客服`
  - discount_request: `算便宜一點 / 打折 / discount`
  - reschedule_request: `改到明天 / 改日期`
  - cancel_request: `算了不訂 / 取消整筆 / 拔單`
- **測試**：`tests/handoff.test.js` 新增 `Round 37.32 regression` test，驗證「我要煙燻雞跟珍珠丸 各一份 這樣多少錢」「最近有哪天開團」「現在還能訂嗎」「怎麼付款」都不觸發 handoff

### 新發現的架構鐵律（要記下來）

#### 4.1 三層架構的 sync 死角
- `sync-canonical.sh` 只同步 canonical files（AGENTS/SOUL/main_idea）
- `sync-mirror.sh` 只同步 dev repo → main mirror
- `sync-producer-config.sh` 只同步 `config.yaml`（每分鐘 cron）
- **沒人同步 `knowledge/` 內的 KB .md 檔案到 L3** → L3 LLM 讀不到菜單
- 修法：新增 `scripts/sync-kb.sh`（rsync L1 → L3）
- **經驗教訓**：新增任何 sync 腳本前先 grep 所有 `sync_*.sh` 看誰覆蓋什麼

#### 4.2 LLM prompt 的「轉報格式」不可外洩
- SOUL.md / main_idea.md 定義的轉報格式（🔔【客服轉報通知】）是給後台 manager 用的
- LLM 看到格式就會複製到客戶回覆（因為它「學到」這個格式是 handoff 的回應方式）
- 修法：在 prompt 裡明確標註「此格式只給 manager 用，客戶回覆走 config.handoff.customer_reply」

#### 4.3 fuzzyTriggers 範圍決定 handoff 觸發頻率
- 關鍵字「貴」「下次」「算了」太寬 → 日常對話誤觸
- 修法：使用完整詞組（`爛掉了`、`算便宜一點`、`改到明天`、`算了不訂`）避免子字串匹配
- 經驗：所有 fuzzy match 都要在 `XXX` 後面加 `^` 或用 `includes` 但要更長詞組

### 心得（給未來 session）

2. **LLM prompt 的 prompt leak 問題**：格式定義本身就是模板，LLM 會自動學會。要明確標註「此格式只給 X 用」
