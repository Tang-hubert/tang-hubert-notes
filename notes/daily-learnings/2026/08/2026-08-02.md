### 用戶補充：OpenClaw & MiniMax 配置優化與問題排查

#### 一、MiniMax M3 1M 上下文與 512k 後台標籤解析
- **現象**：帳號為 Plus 方案，但後台 Consumption 紀錄同時出現 MiniMax-M3-512k 與 MiniMax-M3-1m
- **真相**：這是 MiniMax API 平台根據單次 Request 輸入 Token 數量（以 512k 為界）自動劃分標記的階梯式計費消耗標籤，並非限制了帳號權限
- **解決方式**：在 openclaw.json 的 MiniMax-M3 下明確寫死 `"contextWindow": 1000000`，確保 OpenClaw 不會提早剪裁歷史對話

#### 二、徹底根除 MiniMax M2.7 的步驟
- **出現原因**：存在於舊的 agents.list（如 bench-minimax-minimax-m2-7）、Sub-agent 預設配置或 Timeout 時觸發的 Fallback 備援
- **完整根除 3 步驟**：
  1. **CLI 刪除 Agent**（注意須為複數 agents）：`openclaw agents delete bench-minimax-minimax-m2-7`
  2. **清理 openclaw.json**：
     - 刪除 `models.providers.minimax.models` 下的 MiniMax-M2.7 宣告
     - 刪除 `agents.defaults.models` 對 M2.7 的引用
  3. **清理目錄與重啟**：刪除 `/home/clawuser/.openclaw/agents/bench-minimax-minimax-m2-7` 目錄，並重啟 Gateway：`openclaw gateway restart`

#### 三、Discord Skill 讀取失敗 (ENOENT) 與 Cron 超時修復
- **ENOENT 檔案讀不到根因**：openclaw.json 的 skills 設定缺少了 `load.extraDirs` 搜尋路徑，導致 Agent 搜尋不到 `/home/clawuser/.openclaw/plugin-skills/discord/SKILL.md`
- **免建立軟連結（Symlink）正規解法**：在 openclaw.json 的 `"skills"` 底下補上 extraDirs 掃描路徑：
  ```json
  "skills": {
    "load": {
      "extraDirs": [
        "/home/clawuser/.openclaw/plugin-skills"
      ]
    }
  }
  ```
  （若透過 CLI 設定，須使用 JSON 陣列格式：`openclaw config set skills.load.extraDirs '["/home/clawuser/.openclaw/plugin-skills"]'`）
- **Cron 120s 超時修復**：背景排程有獨立 120 秒超時限制，可於 openclaw.json 根層級加入：
  ```json
  "cron": {
    "timeoutSeconds": 300
  }
  ```

#### 四、openclaw.json 健康度優化與參數調校

1. **compaction.reserveTokensFloor**：
   - 原設定 100000 過大
   - 建議：調降至 20000-40000，避免小容量模型在對話容量才剛過半就被強行壓縮對話

2. **agents.defaults.timeoutSeconds**：
   - 原設定 7200 秒（2 小時）過高
   - 建議：對話類 Agent 調降至 300-600 秒（5-10 分鐘），防止 API 連線卡死時 Channel 長時間無回應

3. **MiniMax Plus 訂閱功能解鎖**：
   - **原生影片與圖片理解**：在 MiniMax-M3 的 input 陣列加入 `"video"`（改為 `["text", "image", "video"]`）
   - **生圖與語音 (Image & Speech)**：直接在對話頻道（Discord/Line）以自然語言下達指令（例如：「請幫我繪製...」）即可自動觸發生圖；語音由已啟用的 voice-call 與 minimax 插件共享 API Key 額度
   - **併發控制**：將 `maxConcurrent` 與 `subagents.maxConcurrent` 設為 3，以符合 Plus 方案最高 3-4 個併發任務的限制

#### 五、Discord 頻道動態綁定與 Agent 切換

- **在 Discord 中切換 Channel 綁定（最便利）**：直接在 Discord 測試頻道對 main Agent 發送指令：
  > 「請幫我執行 CLI 命令，把當前 Channel 綁定給 external-user：openclaw agents bind --agent external-user --bind discord:<Channel_ID>」

- **Terminal 手動切換指令**：
  - 綁定：`openclaw agents bind --agent external-user --bind discord:<Channel_ID>`
  - 解綁：`openclaw agents unbind --agent external-user --bind discord:<Channel_ID>`
