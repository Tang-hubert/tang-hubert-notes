#### T-2：sync-canonical.sh 對 dangling symlink 失敗是已知 bug

**失敗訊息**：
```
cp: not writing through dangling symlink '/home/clawuser/.openclaw/agents/external-user/SOUL.md'
```

**根因**：L3 root 的 SOUL.md / main_idea.md 是 `knowledge/` subdir 的 symlink，但 cp 不會寫穿 symlink。

**修法（SOP）**：
```bash
# 1. rm dangling symlink
rm -f $L3_ROOT/$FILE
# 2. 直接 cp（會到 knowledge/ subdir）
cp -v docs/production-prompt/$DATE/$FILE $L3_ROOT/knowledge/$FILE
# 3. 重建 symlink（指向絕對路徑）
ln -sf $L3_ROOT/knowledge/$FILE $L3_ROOT/$FILE
# 4. MD5 驗證
md5sum docs/production-prompt/$DATE/$FILE $L3_ROOT/knowledge/$FILE
```

**檔案位置**：
- L3 root: `/home/clawuser/.openclaw/agents/external-user/{SOUL,main_idea}.md` (symlink)
- L3 實體: `/home/clawuser/.openclaw/agents/external-user/knowledge/{SOUL,main_idea}.md`
- Dev repo: `docs/production-prompt/2026-08-04/{SOUL,main_idea}.md`

#### T-3：TypeScript brace matching 失敗時不要用 python sed

Round 37.11 我用 python regex 改 `}` 數，結果失敗 3 次（187 `{` vs 192 `}`，差 5 個）。

**最終修法**：`awk` 暴力算 `{` `}` 數 + `python -c "src[:-(210-210)]"` 切掉多餘。

**教訓**：
- **L1/L2 程式碼層修改用 Node + read 工具** — 不要用 exec 跑 python / awk 編輯源碼。
- **brace counting 是 token-level，需要 AST tool**（如 @typescript-eslint/parser），不是 regex。

#### T-5：Worker 雙路由衝突的偵測 SOP

當 Round 31 P0.4 + Round 37 R2 同時存在於 Worker src/index.ts，每次修改都要 grep：

```bash
# 找出所有菜單路由
grep -n "MENU_IMAGE_URLS\|getMenuImageUrls\|isMenuImageQuery" src/index.ts
# 找出所有 FAQ 路由
grep -n "FAQ_IMAGE_URL\|FAQ_KEYWORDS" src/index.ts
# 找出所有 .slice 或長度限制
grep -n "\.slice\|length\s*<\|\<\s*[0-9]" src/index.ts
```

**原則**：**同一資源只能有一條活躍路由**。否則輸入永遠先匹配先觸發（語法上層優先順序）。
