### 關鍵發現與教訓

#### 1. LINE push infinite loop 緊急事件（08:29 處理）
**根因**：`src/index.js` line 50-58 沒擋 `HUMAN_HANDOFF` 狀態重複觸發 handoff
**修法**：雙層保護（HUMAN_HANDOFF guard + 1分鐘 debounce）
**教訓**：state machine 轉換處要明確擋同狀態重複觸發

#### 2. OpenClaw exec redact `***`
- 測試 hardcode `***` 是 OpenClaw 自動 redact 結果，不是 placeholder
- 應從 `getLineBotToken()` / `getPaymentConfig()` / XDG secrets 讀真實值
- 解決：src/config.js 加 env var fallback

#### 3. Sheets API 啟用步驟
- 預設 sheet 名稱是「工作表1」不是「Orders」
- 中文 sheet name 需單引號包裝避免 range parse error
- 解決：getFirstSheetName() 從 metadata auto-discover

#### 4. autoOrder postOrder 接受 201 Created
- api-server POST /api/orders 回 `201 Created`（POST 建立資源的標準）
- 條件寫 `res.statusCode === 200` 會誤判失敗
- 修：`res.statusCode === 200 || res.statusCode === 201`

#### 5. notifyHubert 失敗不該算 autoOrder 失敗
- 訂單建好但 LINE 429（notifyHubert 失敗）被 outer try catch 接到 → success:false
- 修：inner try-catch 包 notifyHubert，失敗只 log warn

#### 6. 89 leaked cloudflared processes 清理
- PID 1543: long-running agent tunnel (--token)，**不要殺**
- 47+ 個 short-running (--url)：可以殺但 OpenClaw 沙箱限制 multi-process kill
- 解決：Hubert 04:55 手動跑 `pkill -f "cloudflared tunnel --url"`（已清理）

#### 7. file mode 555/664 差異
- Layer 1 chmod 555 保護 main 鏡像
- production runtime 檔是 mode 664（OpenClaw exec 可寫）
