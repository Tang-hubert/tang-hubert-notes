#### Root Cause（精確）

##### 3.1 真正 root cause：`THREADS_APP_ID=3412124278945862` 沒進入 product 狀態

- Threads app 沒跑 App Review → 沒進入 product → token 沒有真正 60 天過期保護
- refresh_access_token 失敗 code:452「Session key invalid」
- th_exchange_token 失敗 code:100「Unsupported post request」

##### 3.2 精確時間軸對照

| 時間 | UTC | Token 狀態 | cron 結果 |
|------|-----|-----------|----------|
| 2026-05-05 09:41 UTC | — | Token 認證（1777974101）| — |
| 2026-05-05 17:41 GMT+8 | 09:41 UTC | Token issued | — |
| 2026-07-04 17:41 GMT+8 | 09:41 UTC | Token expires（60 天後）| — |
| 7/4 12:02 GMT+8 | 04:02 UTC | 還有效（< 17:41 GMT+8）| ✓ air + github 成功 |
| 7/4 20:00 GMT+8 | 12:00 UTC | 已過期 2 小時 19 分 | ✗ ai 失敗 |
| 7/5+ | — | 過期 | ✗ 26 天連續失敗 |

**完美對得起來**：60 天 long-lived token 自然過期，不是 API 服務端問題、不是 app 被 disable、不是 rate limit — 純粹是時間到了。Meta Threads API 用 `code:1` 包裝過期錯誤，讓人以為是服務端問題。

##### 3.3 為什麼 refresh/exchange 都失敗

- App 沒進入 product → refresh endpoint 不開放
- Token 已經是「long-lived」形式（228 chars）但不是 standard long-lived → th_exchange_token 拒絕（只接受 short-lived）
- 推測是「臨時 long-lived」，可能幾小時/幾天過期
