### 教訓整合（8 條 從 5 個 round 累積）

1. **PRODUCTION RUNTIME CANONICAL 標頭是設計意圖，不是 bug** — `printf '%s'` 加 `echo` 是原始意圖（heredoc 沒 trailing newline，printf 漏一個，echo 加一個）。改成 `printf '%s\n'` 確保 newline + Check 10 改 `tail -n +14` 跳 13 行。

2. **sync-config.sh 多次運行會累積 duplicate section** — 原始 script 沒 deduplication 邏輯，每次跑都追加 section。Round 16 修法：deeplink check 整段 marker 存在就跳過。

3. **Fuzzy matching 初始 bestScore 必須是合理阈值** — 從 `-Infinity` 開始會讓任何微訊號都匹配（false positive 滿天飛）。`minCombined=0.2` 確保匹配的合併分數必須顯著 > 0.2 命中。

4. **Short keywords (≤2 chars) 不允許 Levenshtein tolerance** — `effectiveMaxDistance = 0` 避免「ai」、「007」、「NT」這種 2-char keyword 被錯位匹配。

5. **wrangle gh token 是 ambient 流程的解法** — `wrangler deploy` 走 OAuth 但 git push 走 https。需要 `git remote set-url origin https://x-access-token:ghp_XXX@github.com/...` 才能 push via gh token。

6. **3 層位置架構是設計意圖：dev repo → main mirror → production runtime** — 永遠在 dev repo 編輯 + sync-mirror + sync-canonical，避免直接改 Layer 1/2/3 任何一層。

7. **KB fuzzy matching 要 3 層** — exact substring (fast path) → Levenshtein (typo handling) → Jaccard n-gram (semantic similarity for Chinese)。單一算法都不夠。

8. **Pre-compaction memory flush 重要** — 每次 session 結束前/記憶壓縮前必須存重要資訊到 `memory/YYYY-MM-DD.md`，不然下次 session 醒來什麼都不記得。
