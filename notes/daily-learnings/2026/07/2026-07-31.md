這次沒用到，因為 Access Token Debugger 直接解決了。但下次遇到 code 100 可以備用。

##### 5.3 Threads API Long-Lived 標準 60 天
```
short-lived (1-2 hours)
  → POST /v1.0/access_token (grant_type=th_exchange_token)
  → long-lived (60 days)
long-lived
  → POST /v1.0/refresh_access_token (grant_type=th_refresh_token)
  → 60 days × N（要 > 24 小時、未過期、user 沒 revoke）
```

##### 5.4 Meta OAuth 工具鏈正確順序
```
1. Graph API Explorer (https://developers.facebook.com/tools/explorer/) → 拿 short-lived token（測試用）
2. Access Token Debugger (https://developers.facebook.com/tools/debug/accesstoken/) → 看狀態 + 延長 long-lived
3. Meta Developer Dashboard → App 設定 + App Review
```

我之前只用了 (1)，沒用 (2)，直接跳到 (3) 的推測。**順序錯了**。

- **production 沒實測就 close-out 是高風險行為**：每次 wrangler deploy 後，至少要傳 1 個文字訊息、1 個貼圖、1 個 command
- **unit test inline 會漏 TDZ**：把 helpers 拆出去獨立 module（src/menuImage.ts），測試從 import 不是 inline
- **推測要明確標註為推測**：下次應該先看 wrangler tail 確認 error，推測要明確寫「推測：...」，修之前先驗證 root cause
- **架構簡化優先**：選技術前先問「這個工具解決的問題真實存在嗎？有沒有更簡單的方案？成本合理嗎？」
- **Hubert 提供本地 Qwen 服務**：本地硬體運算能力可以拿來做 batch jobs（不需要 real-time）
