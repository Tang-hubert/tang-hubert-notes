### P0 修復：LINE Bot 完全不回覆問題

**問題：** 15:06 GMT+8 發現 LINE Bot 完全沒有回覆
**證據：** session log 顯示 15:58-16:09 期間 session 不斷 stall + recovery + re-stall（11分鐘）

**根本原因：**
- Cognee memory plugin 的 `before_prompt_build` hook timeout（15秒）反覆中斷 session
- 每次 agent 處理 LINE 訊息 → Cognee recall timeout → session stall/abort/re-queue → 惡性循環

**修復路徑：**
1. 嘗試 1：Cognee timeout 15s → 45s → 無效

### Session 持久化議題（OpenClaw 預設行為）

**問題：** 為什麼每過一天先前的 session 就沒有原本的 session 紀錄？

**根因：** OpenClaw 預設每天凌晨 4:00（當地主機時間）做 daily reset，產生新 `sessionId`，讓 session 紀錄「消失」

**設計目的：** 避免 context 無限累積，但對跨天開發工作不方便

**解決方案 A（推薦）：改閒置制**
```json
"session": {
  "dmScope": "per-channel-peer",
  "reset": {
    "mode": "idle",
    "idleMinutes": 1000000
  }
}
```
- 約 694 天，實際上等於不 reset

**解決方案 B：完全停用 compaction**
```json
"agents": {
  "defaults": {
    "compaction": {
      "mode": "off"
    }
  }
}
```
- 代價：對話太長會觸發 model context limit 錯誤
