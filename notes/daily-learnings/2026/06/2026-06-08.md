### LINE Webhook 長訊息 401 修復（2026-06-08 18:00-19:00）

**問題：** LINE 長訊息（100字+）→ Worker → OpenClaw → 401 Unauthorized
- 短訊息（0-20字）✅ 正常
- 長訊息（100-150字）❌ 401

**根本原因：**
1. Worker 收到 LINE webhook 時驗證 signature ✅
2. Worker 修改 body（過濾 blocked events）後轉發
3. **轉發時仍使用原始 signature**（針對原始 body 計算）
4. OpenClaw 收到 modified body + 原始 signature → 驗證失敗 → 401

**修復方案：**
```typescript
async function generateLINESignature(bodyText: string, channelSecret: string): Promise<string> {
  const encoder = new TextEncoder();
  const keyData = encoder.encode(channelSecret);
  const key = await crypto.subtle.importKey('raw', keyData, { name: 'HMAC', hash: 'SHA-256' }, false, ['sign']);
  const signatureBuffer = await crypto.subtle.sign('HMAC', key, encoder.encode(bodyText));
  return btoa(String.fromCharCode(...new Uint8Array(signatureBuffer)));
}
```

**轉發時：**
- 構造 `newBody`（過濾 blocked events）
- 使用 `generateLINESignature(newBody, env.LINE_CHANNEL_SECRET)` 產生**新** signature
- Header: `'X-Line-Signature': newSignature`

**部署結果：**
- Worker Version ID: `2eb126a9-7041-4f86-aa8a-c99ff73ec0d5`
- URL: `https://external-user-line-security.kaden1122123.workers.dev`
- 測試結果：✅ 長訊息不再 401

**關鍵教訓：**
> 任何修改 body 的 middleware，都必須重新計算 signature。轉發時不能使用原始 signature，必須針對新 body 重新產生。
