### ⚠️ 重要教訓

**教訓 1：「完成」的定義要嚴格**
- 第一次 Session G commit (`ef54879`) brtclaw 以為「lint 過 = 完成」，沒實際看 CI
- Hubert 抓到「session 完成定義太草率」
- 結果：CI fail（時區問題）浪費 1 個 commit
- **新 SOP**：每個 commit + push 後必看 `gh run view`，CI success 才回報

**教訓 2：CI 跟本機是不同環境**
- 本機 TZ=Asia/Taipei，CI runner TZ=UTC
- 同樣的測試、不同的時區會 fail
- **新做法**：任何依賴「外部環境」的邏輯，必須有「明確設定」層

**教訓 3：business flag 必須 fail-fast**
- awaitingPayment.js 改成 fail-fast（無 default value），config 缺失立即拋錯
- 比「容錯 fallback」好，因為：
  - 避免隱藏錯誤（看起來正常但實際沒讀到 config）
  - 設定錯誤立即被發現
- 但要注意：fail-fast 行為要跟業務語意一致（notifier 應該 return false，csvWriter 應該 throw）
