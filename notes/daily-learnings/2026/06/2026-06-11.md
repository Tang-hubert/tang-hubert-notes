## Notes

### Session 效能管理討論

**問題：** 是否該重開 session 來避免效能下降？

**結論：不用重開**

| 論點 | 說明 |
|------|------|
| Session 隔離乾淨 | 每個 session 獨立 context，互不影響 |
| 效能瓶頸是單一 session context 累積 | 不是 session 數量 |
| 重開會失去 project state | i-En / Threads / cron jobs 追蹤狀態都會消失 |
| Session Context Monitor 已自動化 | 每晚 22:00 自動濃縮，是真正的效能管理 |

**策略：** 與其重開，不如
1. 先讓現有系統跑順（i-En 跑幾輪、Threads 發幾篇）
2. 觀察到的問題寫進 MEMORY.md（新 session 自然拿到乾淨起點）
3. 真的遇到 context 瓶頸再開新 session

### 雞肉團購客服專案 — 系統整理
