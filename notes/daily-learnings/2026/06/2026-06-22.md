### Session 5：Headroom 完整實作（v0.1，待驗證）

**決策：** 採用 `chopratejas/headroom` context 壓縮 proxy，60-95% token 減少

**安裝與設定：**
- Python 3.12 + venv 隔離（`headroom/.venv/`）
- 安裝 `headroom-ai[proxy,code]`（不裝 ml 避免 PyTorch）
- systemd user service：`~/.config/systemd/user/headroom-proxy.service`
- 監控 cron 每 5 分鐘跑（`scripts/monitor-headroom.sh`）

**關鍵發現：** OpenClaw 用 **Anthropic API 格式**（`baseUrl: https://api.minimax.io/anthropic`），不是 OpenAI
- v0.1 用 OpenAI backend 搞錯 → 修正成：
  - `ANTHROPIC_TARGET_API_URL=https://api.minimax.io/anthropic`
  - `--backend anthropic --anthropic-api-url ${ANTHROPIC_TARGET_API_URL}`

**當前狀態：** headroom proxy 已停止，OpenClaw 仍走 direct MiniMax endpoint

**評估數據（官方）：**
- 準確度：GSM8K/TruthfulQA ±0.000，HTML extraction F1 0.919，QA +0.02
- 延遲：proxy overhead 52ms median vs LLM 2-10s（< 3% 增加）
- 11/12 場景淨獲益

**設計原則：分層部署**
- 新工作層（i-En pipeline、Threads 自動發文）→ 走 headroom
- 舊 cron 層（Memory Archive、Config Backup、Session Monitor）→ 維持 direct endpoint
- 理由：避免單點失敗影響所有 cron + 壓縮會破壞 KV cache

1. 啟用修正版 headroom 並驗證（Anthropic backend）
2. 跑 audit 模式一週看 token 節省
3. 寫 CRON_JOBS_MAP.md（區分新 vs 舊 cron jobs）
